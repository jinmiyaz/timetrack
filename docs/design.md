# TimeTrack - 要件定義・基本設計

## 1. 概要

Toggl Track ライクな時間記録アプリケーション。  
ブラウザ上で動作し、外部ネットワークへの接続を一切行わない。ローカルファイルシステムにデータを永続化する。

---

## 2. 要件定義

### 2.1 機能要件

| ID | 機能 | 説明 |
|----|------|------|
| F-01 | タイマー制御 | スタート／ストップでタスクの作業時間を計測する |
| F-02 | プロジェクト管理 | プロジェクトを作成・選択できる。プロジェクトには識別色を設定できる |
| F-03 | タスク入力 | 各タイムエントリにタスク名（作業内容）を入力できる |
| F-04 | タイムエントリ一覧 | 記録した時間を一覧表示する。日付ごとにグループ化する |
| F-05 | 集計表示 | プロジェクト別・タスク別に合計時間を集計して表示する |
| F-06 | エントリ編集 | 記録済みのタイムエントリを編集・削除できる |
| F-07 | 手動エントリ追加 | タイマーを使わず、開始・終了時刻を手動で入力して記録できる |
| F-08 | データ保存 | 指定フォルダに JSON ファイルとしてデータを保存する |
| F-09 | データ読込 | 起動時に保存ファイルからデータを復元する |

### 2.2 非機能要件

| ID | 項目 | 説明 |
|----|------|------|
| NF-01 | ネットワーク非依存 | 外部CDN・API等を一切使用しない。全リソースをローカルに保持する |
| NF-02 | 単一HTML構成 | HTML・CSS・JS をひとつのファイルにまとめ、追加ビルド不要とする |
| NF-03 | ブラウザ互換 | Chrome / Edge / Firefox / Safari の最新版で動作する |
| NF-04 | レスポンシブ | デスクトップ（1024px以上）を主対象とし、タブレットでも最低限操作可能 |


### 3.2 データ保存方式

**方式: File System Access API + localStorage フォールバック**

ブラウザからローカルフォルダへ直接ファイルを読み書きするために **File System Access API** を使用する。

| 観点 | 説明 |
|------|------|
| 書き込み | `showDirectoryPicker()` でフォルダを選択 → `FileSystemFileHandle` 経由で `data.json` を書き込む |
| 読み込み | 選択済みフォルダから `data.json` を読み取る |
| 自動保存 | データ変更のたびに自動保存する（デバウンス 1 秒） |
| フォールバック | API 非対応ブラウザでは localStorage に保存し、手動ダウンロード／アップロードで JSON ファイルをやり取りする |
| 対応状況 | Chrome / Edge は完全対応。Firefox / Safari は非対応のためフォールバック動作 |

**フォルダ選択フロー:**

```
初回起動 → 「保存先フォルダを選択」ボタン表示
  ↓ クリック
showDirectoryPicker() → ユーザーがフォルダ選択
  ↓
フォルダ内に data.json があれば読み込み（データ復元）
  ↓
以降、データ変更のたびに data.json へ自動書き込み
```

### 3.3 データモデル

```json
{
  "version": 1,
  "projects": [
    {
      "id": "proj_abc123",
      "name": "クライアントA案件",
      "color": "#4CAF50",
      "createdAt": "2026-04-03T10:00:00.000Z"
    }
  ],
  "entries": [
    {
      "id": "entry_xyz789",
      "projectId": "proj_abc123",
      "task": "設計書レビュー",
      "startTime": "2026-04-03T10:00:00.000Z",
      "endTime": "2026-04-03T11:30:00.000Z",
      "duration": 5400
    }
  ],
  "activeTimer": {
    "projectId": "proj_abc123",
    "task": "コーディング",
    "startTime": "2026-04-03T14:00:00.000Z"
  }
}
```

| フィールド | 型 | 説明 |
|-----------|-----|------|
| `version` | number | データフォーマットのバージョン。将来のマイグレーション用 |
| `projects[].id` | string | `proj_` + ランダム文字列。`crypto.randomUUID()` で生成 |
| `projects[].color` | string | 16進カラーコード。8色のプリセットから選択 |
| `entries[].duration` | number | 秒数。`endTime - startTime` から算出 |
| `activeTimer` | object \| null | 実行中のタイマー。null ならタイマー停止中 |

### 3.5 主要な処理フロー

**タイマー開始〜停止:**

```
1. ユーザーがタスク名入力・プロジェクト選択
2. ▶ ボタンクリック
3. activeTimer に startTime = now() をセット → 保存
4. setInterval(1s) で経過時間を表示更新
5. ■ ボタンクリック
6. endTime = now(), duration を算出
7. entries に新エントリ追加、activeTimer を null に → 保存
```

**データ保存（デバウンス付き自動保存）:**

```
1. データ変更イベント発生
2. 1秒のデバウンスタイマーをリセット・開始
3. タイマー発火後:
   a. File System Access API 利用可能 → data.json に書き込み
   b. 利用不可 → localStorage に保存
```

### 3.6 技術スタック

| 項目 | 選定 | 理由 |
|------|------|------|
| 言語 | Vanilla JavaScript (ES2022) | ビルド不要、外部依存なし |
| スタイル | CSS（HTML内に埋め込み） | 外部ファイル不要 |
| 状態管理 | シンプルなオブジェクト + イベントベース更新 | フレームワーク不要な規模 |
| ID 生成 | `crypto.randomUUID()` | ブラウザネイティブ、衝突なし |
| ファイルI/O | File System Access API | ブラウザからローカルフォルダに直接読み書き |

## 4. 実装方針

### 4.1 ファイル構成

```
timetrack/
├── docs/
│   └── design.md          ← 本ドキュメント
└── index.html             ← アプリケーション本体（HTML + CSS + JS を単一ファイルに格納）
```

### 4.2 JavaScript モジュール構成（index.html 内）

論理的なモジュール分割を以下のように行う（物理ファイルはすべて index.html 内）:

| モジュール | 責務 |
|-----------|------|
| `StorageAdapter` | File System Access API / localStorage の切り替え、読み書きを担当 |
| `AppState` | データモデルの保持、変更通知、自動保存トリガー |
| `TimerController` | タイマーの開始・停止・経過時間計算 |
| `UIRenderer` | DOM の構築と更新。状態変更に応じて再描画 |
| `App` | 初期化、モジュール間の連携 |

### 4.3 スタイル方針

- Toggl Track を意識したダークテーマ基調のデザイン
- CSS カスタムプロパティでカラーパレットを定義
- 外部フォント不使用（`system-ui` フォントスタックを使用）

## 5. 制約・前提・リスク

| 項目 | 内容 |
|------|------|
| File System Access API の制限 | Chrome / Edge のみ完全対応。Firefox / Safari ではフォールバック（localStorage + ファイルダウンロード）動作となる |
| セキュリティプロンプト | フォルダ選択時にブラウザが権限確認ダイアログを表示する。ブラウザ再起動時に再選択が必要になる場合がある |
| データ整合性 | 複数タブでの同時編集は非対応（単一タブ使用を前提） |
| タイマー精度 | `setInterval` ベースのため秒単位の精度。ブラウザのバックグラウンドタブ制限の影響を受ける可能性があるが、`startTime` を基準に算出するため実時間は正確 |
