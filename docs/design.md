# TimeTrack - 要件定義・基本設計

## 1. 概要

Toggl Track ライクな時間記録アプリケーション。  
ブラウザ上で動作し、外部ネットワークへの接続を一切行わない。ローカルファイルシステムにデータを永続化する。

---

## 2. 要件定義

### 2.1 機能要件

| ID | 機能 | 説明 |
|----|------|------|
| F-01 | タイマー制御 | スタート／ストップでタスクの作業時間を計測する |
| F-02 | プロジェクト管理 | プロジェクトを作成・選択できる。プロジェクトには識別色を設定できる |
| F-03 | タスク入力 | 各タイムエントリにタスク名（作業内容）を入力できる |
| F-04 | タイムエントリ一覧 | 記録した時間を一覧表示する。日付ごとにグループ化する |
| F-05 | 集計表示 | プロジェクト別・タスク別に合計時間を集計して表示する |
| F-06 | エントリ編集 | 記録済みのタイムエントリを編集・削除できる |
| F-07 | 手動エントリ追加 | タイマーを使わず、開始・終了時刻を手動で入力して記録できる |
| F-08 | データ保存 | 指定フォルダに JSON ファイルとしてデータを保存する |
| F-09 | データ読込 | 起動時に保存ファイルからデータを復元する |

### 2.2 非機能要件

| ID | 項目 | 説明 |
|----|------|------|
| NF-01 | ネットワーク非依存 | 外部CDN・API等を一切使用しない。全リソースをローカルに保持する |
| NF-02 | 単一HTML構成 | HTML・CSS・JS をひとつのファイルにまとめ、追加ビルド不要とする |
| NF-03 | ブラウザ互換 | Chrome / Edge / Firefox / Safari の最新版で動作する |
| NF-04 | レスポンシブ | デスクトップ（1024px以上）を主対象とし、タブレットでも最低限操作可能 |

### 3.2 データ保存方式

**方式: File System Access API + localStorage フォールバック**

ブラウザからローカルフォルダへ直接ファイルを読み書きするために **File System Access API** を使用する。

| 観点 | 説明 |
|------|------|
| 書き込み | `showDirectoryPicker()` でフォルダを選択 → `FileSystemFileHandle` 経由で JSON ファイルを書き込む |
| 読み込み | 選択済みフォルダから JSON ファイルを読み取る |
| 自動保存 | データ変更のたびに自動保存する（デバウンス 0.4 秒）。変更のあった月のファイルと meta.json だけを書く |
| 保存失敗時 | 変更内容を保持したままヘッダーにエラーを表示し、指数バックオフで自動再試行する |
| ハンドル永続化 | 選択したディレクトリハンドルを IndexedDB に保存し、次回起動時に自動復元する |
| フォールバック | API 非対応ブラウザでは localStorage に保存し、手動ダウンロード／アップロードで JSON ファイルをやり取りする |
| 対応状況 | Chrome / Edge は完全対応。Firefox / Safari は非対応のためフォールバック動作 |

**推奨のデフォルト保存先:**

| OS | パス |
|----|------|
| macOS | `~/.timetrack` |
| Windows | `%LOCALAPPDATA%\.timetrack`（例: `C:\Users\username\AppData\Local\.timetrack`） |

フォルダが存在しない場合はOSのファイルマネージャー等で事前に作成する。ブラウザの File System Access API の制約上、プログラムから任意パスを指定することは不可能なため、初回のみユーザーが手動で選択する。

**フォルダ選択フロー:**

```
初回起動
  → IndexedDB に保存済みハンドルなし
  → 「保存先フォルダ選択」ボタン表示
      ↓ クリック
  showDirectoryPicker() → ユーザーが .timetrack フォルダを選択
      ↓
  ハンドルを IndexedDB に保存
      ↓
  フォルダ内にデータがあれば読み込み（データ復元）
      ↓
  以降、データ変更のたびに自動書き込み

2回目以降の起動
  → IndexedDB からハンドルを復元
  → queryPermission() == 'granted' → 自動接続（ユーザー操作不要）
  → queryPermission() == 'prompt'  → 「保存先フォルダに再接続」画面を表示
                                       （古い localStorage のデータで作業して後で上書きする事故を防ぐため、
                                        接続するまでデータを読み込まない）
                                       クリック後 requestPermission() で再接続
```

**既存データのあるフォルダへの接続:**

表示中のデータに、選んだフォルダに無いプロジェクト・エントリがある場合は「マージして使う / フォルダのデータのみ / キャンセル」を選ばせる。
マージは ID 単位で、フォルダ側を優先して不足分だけを追加する。

**読み込みエラー時:**

meta.json や entries_YYYY-MM.json が JSON として壊れている場合は読み込みを中止し、上書きを防ぐため保存を停止する（読み取り専用）。
ファイルを修正して「再読み込み」するか、別のフォルダを選択する。

**meta.json が無い／空のとき:**

月別ファイルの記録は常にすべて読み込み、プロジェクト・実行中タイマーを次の順で補ってから meta.json を書き直す。

| 状況 | プロジェクト・タイマーの取得元 |
|------|------|
| 使用中に meta.json が消えた（外部の変更の取り込み、保存停止中からの再読み込み） | 表示中のデータ（data.json は使わない） |
| 起動時・フォルダ選択時で data.json がある | data.json。月別ファイルと同じ ID のエントリは月別ファイルを優先し、data.json にしか無いエントリを追加する |
| どちらも無い | なし（記録だけ読み込む） |

data.json を使った場合、月別ファイルに data.json に無い記録があれば「meta.json が失われたフォルダ」と判断して、
data.json の実行中タイマーは古いものとして破棄し、復元した旨をダイアログで知らせる（data.json 作成後のプロジェクトの変更は戻り、
削除した記録が戻ることがある）。月別ファイルに data.json に無い記録が無ければ、移行の中断とみなして移行を完了する。

**同期:**

| 対象 | 方式 |
|------|------|
| 同じブラウザの別タブ | 保存完了を BroadcastChannel で通知し、受け取ったタブが再読み込みする |
| localStorage モードの別タブ（旧バージョン含む） | `storage` イベントで再読み込み |
| 他の端末・同期ツール・旧バージョンによるフォルダの変更 | ウィンドウがフォーカスされたときに各ファイルの lastModified を比較し、変わっていれば再読み込み |

### 3.3 データモデル

**互換性の原則:** 保存形式は旧バージョンから変更しない（`version: 1`）。新旧どちらのバージョンでも同じフォルダ・localStorage・エクスポートファイルを読み書きできることを `tests/compat.test.mjs` で検証している。

- 未知のフィールド（プロジェクト・エントリ・meta のトップレベル）は保持して書き戻す。`version` も読み込んだ値のまま書き戻す
- 時刻を変更していない編集では `startTime` / `endTime` の文字列を書き換えない
- 新規作成する ID・キー順は旧バージョンと同じ（`proj_` / `entry_` + 16進 8 文字）
- UI 設定（テーマ等）はユーザーデータに含めず、localStorage キー `timetrack_prefs` に保存する

**保存ファイル:**

| 保存先 | 内容 |
|--------|------|
| `meta.json` | `{ version, projects, activeTimer }` |
| `entries_YYYY-MM.json` | エントリの配列。`startTime` のローカル年月で振り分け、開始時刻順に並べる |
| `data.json` | 旧形式（全データを 1 ファイル）。meta.json が無いときだけ読み込み、月別形式へ移行する（既存の月別ファイルの記録は上書きしない）。ファイルはバックアップとして残す |
| localStorage `timetrack_data` | フォルダ未選択時 / 非対応ブラウザ。全データを 1 つの JSON で保存 |
| エクスポートファイル | `{ version, projects, activeTimer, entries }`（localStorage と同じ形） |

読み込み時の自己修復: 同じ ID のエントリが複数の月ファイルにある場合（タイムゾーン変更などで発生しうる）は開始月と一致するファイルのものを採用し、該当する月のファイルを書き直す。

**1 つのオブジェクトにまとめた形（エクスポート / localStorage / 旧 data.json）:**

```json
{
  "version": 1,
  "projects": [
    {
      "id": "proj_abc123",
      "name": "クライアントA案件",
      "color": "#4CAF50",
      "createdAt": "2026-04-03T10:00:00.000Z"
    }
  ],
  "entries": [
    {
      "id": "entry_xyz789",
      "projectId": "proj_abc123",
      "task": "設計書レビュー",
      "startTime": "2026-04-03T10:00:00.000Z",
      "endTime": "2026-04-03T11:30:00.000Z",
      "duration": 5400
    }
  ],
  "activeTimer": {
    "projectId": "proj_abc123",
    "task": "コーディング",
    "startTime": "2026-04-03T14:00:00.000Z"
  }
}
```

| フィールド | 型 | 説明 |
|-----------|-----|------|
| `version` | number | データフォーマットのバージョン。将来のマイグレーション用 |
| `projects[].id` | string | `proj_` + ランダム文字列。`crypto.randomUUID()` で生成 |
| `projects[].color` | string | 16進カラーコード。12色のプリセットまたは任意色 |
| `projects[].archived` | boolean（任意） | true ならアーカイブ済み（新規計上不可） |
| `entries[].duration` | number | 秒数。`endTime - startTime` から算出 |
| `entries[].task` | string | タスク名。空の場合は `(名称なし)` を保存する |
| `entries[].projectId` | string \| null | 削除済みプロジェクトの ID が残っている場合も保持する（表示上は「プロジェクトなし」） |
| `activeTimer` | object \| null | 実行中のタイマー `{ task, projectId, startTime }`。null ならタイマー停止中 |

### 3.5 主要な処理フロー

**タイマー開始〜停止:**

```
1. ユーザーがタスク名入力・プロジェクト選択
2. ▶ ボタンクリック
3. activeTimer に startTime = now() をセット → 保存
4. 毎秒（秒の境界に合わせて）経過時間・タブのタイトル・今日／今週の合計を更新
5. ■ ボタンクリック
6. endTime = now(), duration を算出（1 秒未満は記録しない）
7. entries に新エントリ追加、activeTimer を null に → 保存
8. トーストの「元に戻す」で、エントリを消してタイマーを再開できる
```

**データ保存（デバウンス付き自動保存）:**

```
1. データ変更イベント発生（変更のあった月を「未保存の月」に追加）
2. 0.4 秒のデバウンスタイマーをリセット・開始
3. タイマー発火後（保存中なら完了後にもう一度）:
   a. フォルダ接続中 → 未保存の月の entries_YYYY-MM.json → meta.json の順に書き込み
   b. それ以外 → localStorage に保存
4. 成功: 他のタブへ通知 / 失敗: 未保存の月を戻し、エラー表示して再試行
5. タブを隠す・閉じるときは即座に保存し、未保存があれば離脱時に警告
```

### 3.6 技術スタック

| 項目 | 選定 | 理由 |
|------|------|------|
| 言語 | Vanilla JavaScript (ES2022) | ビルド不要、外部依存なし |
| スタイル | CSS（HTML内に埋め込み） | 外部ファイル不要 |
| 状態管理 | シンプルなオブジェクト + イベントベース更新 | フレームワーク不要な規模 |
| ID 生成 | `crypto.randomUUID()` | ブラウザネイティブ、衝突なし |
| ファイルI/O | File System Access API | ブラウザからローカルフォルダに直接読み書き |
| ハンドル永続化 | IndexedDB | 選択済みディレクトリハンドルをセッション間で保持 |

## 4. 実装方針

### 4.1 ファイル構成

```
timetrack/
├── docs/
│   └── design.md          ← 本ドキュメント
├── tests/
│   ├── compat.test.mjs    ← 保存データ互換性テスト（node --test tests/）
│   └── legacy/storage-v1.js ← 旧バージョンの保存処理（参照実装）
└── index.html             ← アプリケーション本体（HTML + CSS + JS を単一ファイルに格納）
```

### 4.2 JavaScript モジュール構成（index.html 内）

論理的なモジュール分割を以下のように行う（物理ファイルはすべて index.html 内）:

`<script id="tt-core">` は DOM に依存しないコア（Node のテストからも読み込む）、もう一方の `<script>` が UI。

| モジュール | 場所 | 責務 |
|-----------|------|------|
| `TT`（ユーティリティ） | core | 日付・時間の整形と解析、データ正規化、月別振り分け、マージ、集計、CSV |
| `TT.StorageAdapter` | core | フォルダ / localStorage / IndexedDB の読み書き、壊れたファイルの検出、外部変更の検知 |
| `TT.Store` | core | データの保持と変更操作（取り消し用スナップショットを返す）、変更通知、未保存の月の管理、自動保存と再試行 |
| UI | app | タイマーバー、仮想スクロールのタイムライン、集計、各モーダル、トースト、キーボード操作、タブ間同期 |

### 4.3 スタイル方針

- Toggl Track を意識したダークテーマ基調のデザイン
- CSS カスタムプロパティでカラーパレットを定義
- 外部フォント不使用（`system-ui` フォントスタックを使用）

## 5. 制約・前提・リスク

| 項目 | 内容 |
|------|------|
| File System Access API の制限 | Chrome / Edge のみ完全対応。Firefox / Safari ではフォールバック（localStorage + ファイルダウンロード）動作となる |
| セキュリティプロンプト | フォルダ選択時にブラウザが権限確認ダイアログを表示する。ハンドルは IndexedDB で永続化されるため再選択は不要だが、ブラウザ再起動後に権限が失効した場合は「再接続」操作（ユーザージェスチャー必須）が必要 |
| データ整合性 | 複数タブは保存ごとに同期する。ただし複数のタブ・端末でほぼ同時に同じ月を編集した場合は、後から保存した方が優先される（ファイル単位の後勝ち） |
| タイマー精度 | 表示は秒単位。バックグラウンドタブでは更新が間引かれることがあるが、`startTime` を基準に算出するため実時間は正確 |
