# TimeTrack

Toggl Track ライクな時間記録アプリ。ブラウザ単体で動作し、外部ネットワークへの接続は一切不要。

## 特徴

- **単一HTMLファイル** - ビルド不要、`index.html` をブラウザで開くだけで使える
- **外部依存ゼロ** - CDN・外部API を使用しない完全オフライン動作
- **ローカルフォルダ保存** - File System Access API でデータを JSON ファイルとして保存
- **データ形式の後方互換** - 保存する JSON は旧バージョンと同一形式。新旧どちらのバージョンでも同じフォルダを読み書きできる
- **ダーク / ライトテーマ** - Toggl Track 風のデザイン。モバイル幅にも対応

## 使い方

### 起動

`index.html` をブラウザで開く。

```sh
open index.html        # macOS
xdg-open index.html    # Linux
start index.html       # Windows
```

### 基本操作

1. **保存先フォルダを選択** - ヘッダーの「保存先フォルダ選択」からデータの保存先を指定
2. **タイマー計測** - タスク名を入力して <kbd>Enter</kbd>（または ▶）で開始。計測中もタスク名・プロジェクトを変更でき、時間表示をクリックすると開始時刻を修正できる
3. **再開** - タイムラインの各エントリの ▶ で、同じタスク・プロジェクトの計測をすぐ再開
4. **手動追加・編集** - 「手動追加」またはエントリのクリックで編集。日時・時間は分単位で入力し、時間欄に `1:30` / `90m` / `1.5h` などと入力すると終了時刻を自動計算（時刻を変更しなければ、タイマーで記録した秒はそのまま残る）
5. **集計** - 「集計」タブで期間（今日・昨日・今週・先週・今月・先月・全期間・任意）を選び、合計・日別グラフ・プロジェクト別・タスク別を確認。CSV 出力も可能

削除・停止・アーカイブなどの操作はトーストの「元に戻す」で取り消せる。

### キーボードショートカット

| キー | 動作 |
|------|------|
| <kbd>N</kbd> / <kbd>/</kbd> | タスク名の入力欄へ移動 |
| <kbd>S</kbd> | タイマーの開始 / 停止 |
| <kbd>1</kbd> / <kbd>2</kbd> | タイムライン / 集計に切り替え |
| <kbd>Enter</kbd> | （タスク名入力中）タイマーを開始。日本語入力の変換確定では開始しない |
| <kbd>Esc</kbd> | ダイアログ・メニューを閉じる |

### データ保存

| ブラウザ | 保存方式 |
|---------|---------|
| Chrome / Edge | File System Access API で選択フォルダに JSON ファイルを自動保存 |
| Firefox / Safari | localStorage に保存。設定画面から JSON のエクスポート / インポートが可能 |

**推奨の保存先フォルダ（初回のみ手動選択）:**

| OS | 推奨パス |
|----|---------|
| macOS | `~/.timetrack`（ホームディレクトリ直下） |
| Windows | `%LOCALAPPDATA%\.timetrack`（例: `C:\Users\username\AppData\Local\.timetrack`） |

フォルダが存在しない場合は事前に作成してから「保存先フォルダ選択」で指定してください。  
一度選択するとブラウザの IndexedDB にハンドルが保存され、次回以降は自動的に再接続します。  
ブラウザ再起動後に権限が失効した場合は起動時に「保存先フォルダに再接続」画面が表示されます（古いブラウザ内データで上書きしてしまう事故を防ぐため）。

**データの安全性:**

- 変更は 0.4 秒後に自動保存。保存失敗時はヘッダーに表示され、自動で再試行する（未保存のままタブを閉じようとすると警告）
- フォルダ内の JSON が壊れている場合は読み込みを中止し、上書きせずに保存を停止する
- `meta.json` が消えた・空になった場合も月別ファイルの記録はすべて残し、プロジェクト設定は表示中のデータ（無ければ旧形式の `data.json`）から作り直す
- 既にデータがあるフォルダに接続するときは、表示中のデータとマージするかを選べる
- 複数タブで開いても、保存のたびに他のタブへ反映される。他の端末・同期ツールによるフォルダの変更もウィンドウに戻ったときに読み込む

## 機能一覧

- タイマー開始 / 停止 / 破棄、計測中のタスク名・プロジェクト・開始時刻の変更
- タスク名の入力補完（プロジェクト選択中はそのプロジェクトの過去のタスク名だけ。未選択時は全履歴から選べ、選ぶと前回のプロジェクトも自動選択）
- プロジェクト管理（名前・カラー〈プリセット 12 色 + 任意色〉・件数と合計時間の表示）
  - 検索できるプロジェクト選択メニュー、メニューからの新規作成
  - アーカイブ / 解除（アーカイブ済みプロジェクトへの新規計上不可。過去データは引き続き表示）
- タイムライン（日別グループ・仮想スクロール・検索・プロジェクト絞り込み・今日 / 今週の合計）
- エントリの編集・削除・再開・手動追加（時間の直接入力、重複時間の警告）
- 集計ビュー（期間プリセットと前後移動、日別 / 月別の積み上げグラフ、プロジェクト別・タスク別、CSV 出力）
- 設定（テーマ、週の開始曜日、時間の表示形式 `1:30:00` / `1:30` / `1.50 h`）
- JSON エクスポート / インポート（マージ・置き換え）

## データ形式（互換性）

保存形式は旧バージョンから変更していません（`version: 1`）。詳細は [docs/design.md](docs/design.md) を参照。

```
保存先フォルダ/
├── meta.json              # { version, projects, activeTimer }
├── entries_YYYY-MM.json   # その月（開始時刻のローカル年月）のエントリ配列
└── data.json              # 旧形式（あれば読み込み時に月別形式へ移行し、バックアップとして残す）
```

- localStorage キー `timetrack_data`、IndexedDB `timetrack_meta` も旧バージョンと同じ
- 未知のフィールドは保持したまま書き戻すため、将来の拡張データも失われない
- テーマなどの表示設定はユーザーデータとは別の localStorage キー `timetrack_prefs` に保存

## テスト

Node.js 18 以上で実行できます（依存パッケージなし）。

```sh
node --test tests/
```

旧バージョンの保存処理と新バージョンの間で、フォルダ・localStorage・エクスポートの各形式を相互に読み書きできること、破損ファイルを上書きしないことなどを検証します。

## ブラウザ対応

|---------|---------|
